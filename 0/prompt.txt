# Phase 1 prompt — Build a reliable asynchronous Maker and live Run Inspector

Implement only Phase 1 of the Unfinished Business roadmap. Replace the blocking Maker request with a durable asynchronous OpenCode run lifecycle and a user-visible Run Inspector. Reliability is the priority; do not begin the broad visual redesign or tool recommendation work.

## Prerequisite

Verify Phase 0's baseline and canonical documentation exist and match the repository. Inspect current state rather than trusting a summary. If the state-schema migration or documentation ownership is unresolved, stop and report the blocker.

## Outcome

Starting Maker must return immediately, persist an identifiable run and OpenCode session, stream understandable progress, survive refresh/restart, interrupt the actual OpenCode session when cancelled, and finish with evidence. A timeout must never silently lose the native session.

## Inspect before editing

- Read the current Maker frontend, experience service, OpenCode guide/client/operation helpers, persistence layer, API routes, tests, and relevant docs.
- Verify the installed OpenCode client/server API for session creation, events, status, interrupt, permissions, diff, and usage. Use the pinned version's actual types/docs rather than memory.
- Inspect current user data without mutating it. Design a forward migration and backup before changing stored records.
- Preserve unrelated and user-owned changes.

## Backend work

- Introduce a durable run record with states such as `QUEUED`, `CONNECTING`, `RUNNING`, `WAITING_PERMISSION`, `VERIFYING`, `SUCCEEDED`, `FAILED`, `CANCELLED`, and `UNKNOWN`.
- Make `POST /api/runs` validate authorization, persist the queued run, and return `202` with a stable run ID without waiting for model completion.
- Persist the OpenCode session/message identifiers before sending work that can mutate files.
- Run work through a bounded in-process coordinator appropriate to the current single-process architecture. Do not add Temporal or another service in this phase.
- Subscribe to OpenCode events when supported; otherwise use the smallest safe status reconciliation required by the installed version.
- Normalize events into a versioned, append-only application event shape with sequence/cursor, timestamp, category, public summary, redacted metadata, and evidence references.
- Add authenticated SSE for run events with heartbeat, cursor/`Last-Event-ID` resume, snapshot resync, and terminal closure behavior.
- On process restart, reconcile non-terminal runs against OpenCode rather than retrying them automatically.
- Make cancellation call OpenCode's native interrupt API. Do not mark a run cancelled until the native outcome is observed or explicitly becomes unknown.
- Make duplicate action IDs idempotent. Prevent double-submit and unsafe retries.
- Record diff, verification results, duration, model/session identity, usage/cost when available, and honest limitations at terminal status.
- Redact prompts, secrets, headers, cookies, environment values, and unrestricted tool arguments/results from stored events and telemetry.

## Frontend work

- Replace the global frozen waiting state with immediate run acknowledgement.
- Add a Run Inspector drawer or tab showing queued, connection, session, model response summaries, tool activity, permission waits, file changes, verification, and final evidence.
- Never show hidden chain-of-thought. Render operational facts and concise user-visible summaries only.
- Reconnect after reload using the run ID and event cursor.
- Provide clear cancel, retry-after-reconciliation, authentication repair, and terminal next actions.
- Replace “This is taking longer than usual” with meaningful live state. A slow run may show elapsed time and the last confirmed event, but must not imply that nothing is happening.
- Keep the existing stage workflow functional and accessible at narrow and wide widths.

## Required tests

Add focused unit/integration tests for:

- immediate `202` response and persisted queued run;
- state transitions and invalid transitions;
- SSE ordering, reconnect, gap resync, heartbeat, and terminal behavior;
- refresh and server restart recovery;
- actual native interrupt handling;
- timeout becoming reconcilable `UNKNOWN`, not fabricated failure;
- duplicate submission/idempotency;
- OpenCode unavailable, authentication failure, provider limit, missing model, permission denial, verification failure, and malformed event;
- event and Sentry secret redaction;
- state migration and backup.

Use deterministic fakes at the boundary; do not require paid inference for automated tests. Run one harmless live OpenCode proof only when the invoking environment already has authorized access.

## Documentation requirements

Update in the same change:

- `docs/ARCHITECTURE.md` for the coordinator, event stream, persistence, and trust boundary;
- `docs/OPENCODE_INTEGRATION.md` for session/event/interrupt behavior and version constraints;
- `docs/OPERATIONS_AND_RECOVERY.md` for restart, reconciliation, cancellation, retention, and unknown outcomes;
- `docs/LOCAL_SETUP.md` for required OpenCode server configuration;
- `docs/IMPLEMENTATION_PLAN.md` with completed acceptance evidence and remaining work;
- `docs/DECISIONS.md` for SSE and in-process coordination choices;
- `docs/CHANGELOG.md` and `README.md` for visible Maker behavior.

If a canonical document does not yet exist, create it with only verified and phase-relevant content. Do not update only the old blueprint.

## Acceptance

- The user sees a saved run and first status within 500 ms under normal local conditions.
- Refresh resumes the same run.
- Restart reconciles rather than duplicating work.
- Cancel invokes OpenCode interrupt.
- Timeout cannot erase the native session reference.
- A terminal result includes diff and verification evidence or explicitly explains why they are unavailable.
- All automated checks pass and documentation matches the implemented API/state schema.

Finish with the required phase handoff and stop. Do not start Phase 2.
